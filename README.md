# 옛한글 OCR — 위키문헌 소도구

한국어 위키문헌(ko.wikisource.org)의 옛한글 문헌 스캔을 읽는 OCR 프로젝트입니다. 19~20세기 한글 및 한자 인쇄본을 대상으로 합니다. 그 이전의 옛한글, 한자, 숫자 등의 특수기호는 인식하지 못합니다.

모델(ONNX, CPU)은 [Toolforge](https://wikitech.wikimedia.org/wiki/Help:Toolforge) 서버에서 돌고, 소도구는 화면만 맡습니다.

| 도구 | 무엇 | 파일 |
|---|---|---|
| **인식 (전사)** | 편집 중인 쪽의 스캔을 읽어 편집 상자에 넣음. 확신이 낮은 글자는 색으로 칠함 | `ocr.js` |
| **교정 (전사대조)** | 이미 전사된 글을 스캔과 맞대어 틀렸을 만한 글자를 짚음 | `compare.js` |
| **영역 지정** | 스캔 위에 상자를 쳐서 자동으로 못 읽은 열 · 글자만 따로 읽음 | `area/` |

도구 주소: <https://old-hangul-ocr.toolforge.org/>

[특수:내사용자문서/common.js](https://ko.wikisource.org/wiki/Special:MyPage/common.js) 에 아래 줄을 넣고 저장한 뒤 새로 고침하세요.

## 쓰는 법

### 인식 (전사)

1. `페이지` 이름공간의 문서(`페이지:…` 형식의 문서)를 편집으로 엽니다.
2. 편집 상자 위의 "인식 (전사)" 를 누릅니다.
3. 읽은 글이 편집 상자에 들어갑니다. 확신이 낮은 글자는 색으로 칠해 보여 줍니다(구문 강조를 켜 두었으면 편집 상자 위에 따로).
4. 인식한 글자가 맞는지 한 번 읽으며 점검한 후 저장해 주세요.

### 교정 (전사대조)

1. 이미 전사문이 있는 `페이지` 문서를 편집으로 엽니다.
2. 편집 상자 위의 "교정 (전사대조)" 를 누릅니다.
3. 의심 자리가 편집 상자 안에 칠해지고, 아래 목록에 스캔 조각이 나옵니다. "바꾸기" 는 그 글자만 바꾸고(Ctrl+Z 로 되돌림), "넘기기" 는 목록 아래로 접습니다.
4. OCR 결과가 틀리는 경우가 종종 있습니다. 왼쪽에 같이 표시되는 스캔 조각이나 원본 파일을 반드시 같이 보면서 골라 주세요.

- 틀(`{{절}}` · `{{u}}` 등)과 서식은 건드리지 않고 인쇄된 글자만 봅니다. 한자 · 숫자는 보지 않습니다.
- 한 쪽에 길게는 수십 초 가량 걸릴 수 있습니다.

### 영역 지정

 `페이지` 문서를 편집으로 연 상태에서 "영역 지정" 단추를 누르면 새 창에서 그 쪽이 열립니다. 또는 <https://old-hangul-ocr.toolforge.org/area/> 주소로 직접 들어가도 됩니다.

열 · 글자 · 여러 열 중 하나로 상자를 쳐서 그 자리만 읽고, 결과를 고쳐 가며 쓸 수 있습니다. 마우스 휠로 확대 · 축소, 오른쪽 단추로 끌어서 옮깁니다. 자동으로 잘 못 읽는 쪽(흐린 쪽 · 열이 붙은 쪽)에 사용하세요.

### 설정 메뉴

단추 줄 오른쪽의 "설정" 에서 고릅니다. 고른 값은 브라우저에 기억됩니다.

- **모델** — 근대 순한글(기본) / 근대 국한문(한자 포함).
- **단** — 자동(파일을 처음 열 때 살펴 정함) 또는 1~5단 직접 지정.
- **띄어쓰기 자동 감지** — 기본 켬. 끄면 글자는 그대로이고 공백만 빠집니다.

문제가 생기면 단추 줄 끝의 작은 "로그" 링크로 기록을 펼쳐 복사해 제보해 주세요.

## 알아 두실 것

- **꼭 눈으로 확인한 뒤 저장하세요.** 색칠되지 않은 자리에도 오류가 글자 100개에 1개 안팎 남습니다. 열 끝의 글자가 빠지는 일도 있습니다.
- 한 쪽에 몇 초~열몇 초 걸립니다(서버 상황에 따라 다름).
- 파일마다 처음 한 번은 판형(몇 단 구성인지)과 글자 간격을 재기 위해 여러 쪽을 받아 살핍니다(1~3분). 서버를 다시 켜면 처음부터 다시 살핍니다.
- **쉼표 · 마침표는 읽은 결과에서 뺍니다.** 문장부호는 OCR 계산을 위해 내부적으로 인식 자체는 하지만 다양한 형태를 모두 대응하기 어려워 출력에서 제외됩니다.
- **개인정보 관련 고지** — 이 도구는 서버를 거칩니다. 스캔은 서버가 위키미디어 공용에서 직접 받고, 편집 상자의 글(전사대조)은 맞대는 데만 쓰고 남기지 않습니다. 접속 기록도 따로 남기지 않습니다.
- **디버그 로그** — 디버그 로그에는 실제 사용 이미지 주소, 크기·해시, 캐시 식별자, 모델·설정 지문, OCR 문자 수·해시·전체 OCR 결과, 선택·재시도한 기하, 열별 요약, 불일치 구간, 상자별 좌표·전사/OCR 글자·확신도가 포함됩니다. 서버가 이를 별도로 저장하지는 않으며, 사용자가 브라우저에서 복사한 로그에만 들어갑니다. 구형 서버 응답에는 진단 정보가 없다고 표시됩니다.

## 어떻게 읽나

1. **자르기** — 쪽에서 열을 찾고, 글자 간격이 고르다고 보고 한 열을 몇 칸으로 자를지 정합니다. 글자 경계를 배운 작은 검출기가 자를 자리를 도와줍니다.
2. **읽기** — 칸마다 CNN(초 · 중 · 종성 머리 셋)이 읽고, 확신이 낮은 글자에 표시를 붙입니다.
3. **전사대조** — 위키문헌의 기존 전사문을 정답지로 삼아 같은 쪽을 맞대어, 어긋난 자리만 짚습니다.

셈은 프로젝트의 파이썬 코드가 정본이고, 서버에서는 torch 대신 같은 모델의 ONNX 파일을 씁니다(글자 · 띄어쓰기 · 표시 모두 같은 결과, 확신값 차이 0.0004 미만).
영역 지정 화면만 `읽기.js`(파이썬을 옮긴 것)를 함께 씁니다.
